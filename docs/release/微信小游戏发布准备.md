# 拾色 · 微信小游戏发布准备

核对日期：2026-10-25。面向“正式微信小游戏、尚未注册账号”的当前情况。本文是接入与发布路线，**当前交付仍是可运行的网页版本，不是已经适配完成的微信小游戏代码包，也尚未提交微信审核**。

## 先做的三件事

1. 在 [微信公众平台](https://mp.weixin.qq.com/) 注册小游戏账号，按平台提示选择实际主体、游戏类目并完成主体验证。游戏名暂定“拾色”，以后台查重和材料要求为准。
2. 首版建议先不做虚拟支付、内购和用户资料授权，让核心关卡可离线体验。无虚拟支付路线、广告变现路线与开通内购的路线有不同材料要求；不能仅凭“个人开发”或“免费”判断所有审核要求。
3. 拿到小游戏 AppID，使用 [微信开发者工具](https://developers.weixin.qq.com/minigame/dev/devtools/download.html) 建立项目。AppID 可供开发适配；不要在聊天或前端代码里放 AppSecret、上传密钥或服务器密码。

注册、资质准备和代码适配可以并行。官方当前发布流程请以 [小游戏接入指南](https://developers.weixin.qq.com/minigame/introduction/guide/) 为准。

## 当前代码距离正式小游戏还有什么

| 当前网页实现 | 微信小游戏需要做的工作 | 当前状态 |
|---|---|---|
| `index.html`、CSS、DOM 菜单、背包、暂停与编辑面板 | 使用 Canvas 绘制界面并实现按钮命中、界面层级与点击阻断 | 待移植 |
| Canvas 2D 关卡、角色、碰撞、材料与机关 | 保留玩法核心，画布初始化接入 `wx.createCanvas()`，核对字体、合成与离屏渲染兼容性 | 可复用，但未在小游戏运行时验证 |
| `pointerdown`、键盘事件、HTML 按钮 | 接 `wx.onTouchStart/Move/End/Cancel`；暂停/改造不能残留输入，保留触屏操作规则 | 待移植 |
| `localStorage` 进度与收集数 | 接微信本地缓存，处理读写失败与旧存档版本 | 待移植 |
| 浏览器 WebAudio 合成音效与配乐 | 核对微信音频接口支持，适配或预生成音频；切后台暂停、回前台恢复 | 待移植与真机验证 |
| 网页横竖屏布局、安全区 | 选定小游戏首版方向，按屏幕尺寸和微信菜单胶囊安全区布局；移动、跳跃、改造能单手辨认 | 待真机适配 |
| Python/Nginx 邀请码网页入口 | 不作为小游戏客户端启动入口；首版关卡随包本地运行，邀请码页继续只服务网页测试版 | 未接微信版本 |
| Git 与网页服务器发布 | 输出 `game.js`、`game.json` 和开发工具项目配置，预览、体验版、版本审核、发布 | 尚无正式小游戏构建产物 |

当前项目适合先做 **Canvas 2D 原生小游戏适配**，复用现有机制与测试。暂不为了上线重写成 Unity 或 3D 游戏。若后续关卡与美术团队规模明显增长，再评估引擎迁移。

官方参考：[开发指南](https://developers.weixin.qq.com/minigame/dev/guide/)、[wx.createCanvas](https://developers.weixin.qq.com/minigame/dev/api/render/canvas/wx.createCanvas.html)、[微信官方小游戏示例](https://github.com/wechat-miniprogram/minigame-demo)。

## 接下来按这个顺序交付

### 第一阶段：完成可玩版本（本轮已做）

- 角色采用护目镜、围巾与灯芯核心，仍按真实可编辑色块绘制。
- 五种材料有独立纹理和图形标识，遗迹背景、机关金属构造与出口造型统一。
- 后半关增加二次配重、上下层往返、水共鸣与火草双徽记组合；保留可选光种。
- 自动通关、材料与机关条件、复活、输入隔离持续验证。

### 第二阶段：小游戏可预览包（待做）

- 分离平台接口、玩法更新、Canvas 渲染与界面；浏览器仍能运行同一玩法核心。
- 新建微信端入口与 Canvas UI，接入存档、触摸、多指操作、音频和前后台事件。
- 输出可在开发者工具导入的小游戏项目，填写真实 AppID；不把空壳目录称为可发布包。
- 使用开发者工具预览二维码，在真实 Android 微信、真实 iPhone 微信测试。Chrome 手机模拟与 WebKit 测试只能补充，不能替代。

### 第三阶段：体验版与提审（需要账号后台配合）

- 上传开发版，建立体验版，邀请实际玩家检查引导、材料理解、难度与卡关。
- 配置名称、图标、简介、适龄提示、类目、隐私声明及后台要求的资料。
- 完成适用的资质审核、小游戏备案/小程序备案与版本审核，满足条件后发布。审核时效不是开发工期保证。
- 不在体验和审核版中加入未经声明或审核后才替换的功能。

## 资质与运营路径

### 不做虚拟支付 / IAA 方向

[官方 IAA 发布指引](https://developers.weixin.qq.com/minigame/introduction/guide/iaa.html)列出了注册、基本信息、类目、适龄、资质、版本审核、小游戏备案与小程序备案等流程。[IAA 资质要求](https://developers.weixin.qq.com/minigame/introduction/guide/zzsh-iaa.html)目前列出了游戏名含英文或“软件”、涉及品牌/公众人物等需要软著或相应授权材料的情形。不要直接沿用旧文章“所有个人小游戏都不用版号/所有小游戏都一定要同一套软著材料”的绝对说法；以实际主体、类目和后台要求办理。

如果首版不投放广告，也应在注册后的发布后台核对所选“无虚拟支付”路径，而不是假定跳过资料与备案。

### 带内购 / IAP 方向

[官方 IAP 发布指引](https://developers.weixin.qq.com/minigame/introduction/guide/iap.html)与[资质审核要求](https://developers.weixin.qq.com/minigame/introduction/guide/zzsh-iap.html)明确涉及网络游戏出版物号核发单、计算机软件著作权登记证书等材料。若以后计划内购，应先规划主体、权利与资质，不将广告版的路径直接套用。

### 备案与隐私

按[小程序备案指引](https://developers.weixin.qq.com/minigame/introduction/guide/xcxba.html)办理实际适用流程。按[小游戏隐私合规指南](https://developers.weixin.qq.com/minigame/introduction/guide/privacy.html)如实披露个人信息处理。首版可以不索取头像、昵称、位置和通讯录；若确无个人信息处理，应按官方后台流程确认，而不是随意写“零收集”。接广告、登录、统计或排行榜后要重新核对 SDK 和接口处理的信息。

游戏本体可以随包本地运行，不需要因为是小游戏就额外购置游戏服务器。将来如果做云存档、排行榜、广告服务或用户服务端，再配置对应后台、网络域名和 HTTPS；当前 `http://IP:8080` 的网页地址不能直接当作小游戏合法业务接口域名使用。
